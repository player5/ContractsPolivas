## УТВЕРЖДЁННАЯ лёгкая обработка очереди

1. Dispatcher читает только опубликованные карточки/полные промпты и выдаёт новые задачи **назначенным** моделям. Он не меняет GitHub, не проверяет содержимое и не вычисляет SHA-256 ради публикации. Буква модели закреплена: `D` только DeepSeek, `G` только Gemini, `C` только GPT. Для неназначенных заданий порядок пригодных свободных исполнителей: **D → G → C**; готовые ID не переназначаются.
2. После `DONE` DeepSeek Dispatcher сохраняет исходный ответ и при **следующем обычном GPT-задании** вставляет короткую служебную секцию и оригинал как данные. Не создаёт отдельной GPT Publisher-задачи.
3. Для Gemini Dispatcher передаёт GPT точные ссылки на **реально сообщённые** результаты на Google Drive. GPT подключён ко всем трём Drive по подтверждению владельца, но доступ к отдельному файлу может отличаться. Служебная секция не переписывает и не копирует файлы Gemini.
4. GPT в рамках своей **основной задачи** сначала смотрит указанные файлы/записи. Если результат есть — отмечает исходную карточку `PROCESSED`, убирает **только строку** из текущего активного `INDEX.md`, сохраняет сами карточки, исходники, результаты и историю. Если результата нет — оставляет запись без изменений и продолжает основную работу. **Без SHA, проверки качества или отдельного Publisher.**
5. Dispatcher лишь перечитывает **статус карточки и отсутствие строки в INDEX**. После учёта предшественника и разрешения зависимостей следующий готовый контракт выдаётся по своему закреплённому исполнителю. Содержательная оценка производится **отдельным Validator**, а не на стадии закрытия очереди.
6. **Срочные исправления** с конечной `F` имеют приоритет над обычными готовыми задачами, не отменяя зависимостей.

**Конкретная зависимость пилота:** `C001D000TST` уже дал ответ в установленном предыдущем UNIVERSAL. Его повторно запускать нельзя. Следующее **обычное** GPT-задание должно сохранить результат и отметить C001 как `PROCESSED`; затем уполномоченный GPT/Producer переводит `V002C001TST` в `PUBLISHED`, и Dispatcher запускает Validator по обычным правилам. **Пока готового GPT-задания нет, очередь ждёт; отдельный запрос только ради уборки не создаётся.**

[Утверждённая нумерация](NUMBERING.md). [Отдельные карточки](contracts/) остаются в GitHub после учёта; удаляется исключительно строка из списка активных. Контроль качества и owner acceptance — отдельные статусы.

**Ограничение реализации:** этот каталог отражает новый утверждённый регламент. Установленный на ЭМ-ПК предыдущий UNIVERSAL до обновления ещё содержит старый Publisher. Сборка лёгкого патча проходит локальные тесты, но реальное браузерное испытание пока NOT VERIFIED.
