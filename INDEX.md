# BROWN SWARM — публичная очередь контрактов

**PUBLISHED / готово к автоматической выдаче: 1.** **WAITING_PUBLICATION / ожидает зависимость: 1.**

В этом тестовом каталоге оставлены **ровно два актуальных контракта**. Dispatcher получает карточки по публичному HTTPS без GitHub-токена, читает полный промпт и проверяет модель/зависимости по данным карточки, без специальных условий для C001 или DeepSeek.

| Contract ID | Тип | Исполнитель | Карточка | Промпт | Состояние |
|---|---|---|---|---|---|
| **C001D000TST** | C / 100 слов | DeepSeek | [C001D000TST](contracts/C001D000TST.md) | [полный промпт](prompts/C001D000TST-DeepSeek.md) | PUBLISHED / READY / I2 A1 |
| **V002C001TST** | V / независимая проверка 100 слов | ChatGPT | [V002C001TST](contracts/V002C001TST.md) | [подробный Validator-промпт](prompts/V002C001TST-ChatGPT.md) | WAITING_PUBLICATION / DISABLED / DEP C001 |

## Автоматический жизненный цикл

1. Dispatcher читает C001 и даёт полный промпт DeepSeek через Firefox, в **новой беседе той же вкладки**. ID: `C001D000TST`, модель D, зависимостей 000, `delivery_id=PUB-C001D000TST-I2-A1`.
2. Worker выдаёт оригинальный ответ, Dispatcher сохраняет его без изменения и вычисляет SHA-256. `DONE` от Worker ещё не означает публикацию.
3. Dispatcher отправляет отдельный динамический **Publisher-промпт** в ChatGPT; он должен записать **точный оригинал** в `results/PUB-C001D000TST-I2-A1.txt`, выполнить readback, сравнить фактический SHA-256 с `ORIGINAL_SHA256`, после успешной сверки перевести C001 в `PROCESSED / RESULT_PUBLISHED` и убрать из активной очереди. При этом публикует зависимый V002 как `PUBLISHED / READY` в карточке и индексе. Не удалять созданные результаты.
4. Dispatcher **сам проверяет опубликованные байты** по публичному HTTPS и не считает GATE выполненным при отсутствующем/несовпадающем SHA. Даже по истечении 120 секунд V002 не должен стартовать без доказательств.
5. После выполнения GATE Dispatcher автоматически выдаёт V002 ChatGPT с полным независимым промптом и метаданными источника/исходным SHA. Validator выдаёт **подробный отчёт**: количество слов, тема, структура, корректность статуса, SHA, аргументы PASS/FAIL и NEXT_EXACT_STEP.
6. Результат V002 тоже передаётся Publisher и после доказанного readback исключается из очереди как `PROCESSED`. Если Validator до интеграции обнаруживает ошибку, он создаёт срочный фикс с конечной **`F`**; это внеочередная задача, но она не обходит собственные зависимости.

**Особенность публикации:** анонимный Dispatcher **не пишет в GitHub**. Запись результата, статуса и переходы индекса выполняет **уполномоченный ChatGPT Publisher** в своём чате. При отсутствии GitHub-прав Publisher возвращает BLOCKED и не изображает фиктивный PROCESSED. Самостоятельный SHA readback со стороны Dispatcher — отдельная проверка; наличие строки PROCESSED в индексe ещё не подтверждает идентичность байтов.

**Нумерация:** [ROLE + сквозной NNN + модель D/G/C + три цифры зависимости + серия + конечная F](NUMBERING.md). Старые тестовые карточки/промпты удалены из текущего дерева по разрешению владельца; историю их Git-коммитов можно просмотреть. Старый файл результата не удаляли — это диагностическое свидетельство другой попытки.

**Приёмка:** пока **NOT RUN / NOT VERIFIED** до реального прохода DeepSeek→Publisher→GitHub readback→Validator. Публичная карточка ≠ факт выполнения.
