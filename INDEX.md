## Общий порядок (не специфичен для теста)

1. Producer публикует карточку с валидным ID, реальным исполнителем, зависимостями, проверками и полным промптом.
2. Dispatcher без встроенных тестовых условий выбирает готовое задание, отправляет его в существующую вкладку модели в **новую беседу**, захватывает полный ответ и статус.
3. Publisher сохраняет **оригинальные байты** по уникальному `delivery_id`, делает readback и сравнивает оригинальный SHA-256 с опубликованным. После подтверждения публикации уполномоченный Publisher/Producer переводит исходный контракт в `PROCESSED` и убирает его из активной очереди.
4. Только после подтверждённого GATE публикуется зависимый Validator, который независимо проверяет **критерии конкретной карточки**, затем тоже выводится из очереди после обработки результата.
5. Срочный фикс, созданный Validator до интеграции, получает конечную `F` (например, `C001D000TSTF`) и приоритет вне обычной очереди **после** удовлетворения зависимостей.

**Текущее ограничение FIX12P4:** историческая проверка конкретного ID C001 и контрольного маркера всё ещё есть в EXE; универсальная маршрутизация не должна делать такой special-case. Отдельная инструкция [Publisher для C001 R2](prompts/C001D000TST-Publisher-ChatGPT-R2.md) пока не загружается программой автоматически; доказательный GATE на SHA также не внедрён. **Не запускать новые карточки как PUBLISHED до проверки исправления.**
