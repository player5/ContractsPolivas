# ContractsPolivas — публичная очередь BROWN SWARM

**Статус:** PUBLIC TASK CATALOGUE. C001D000TST (DeepSeek) и V002D001TST (ChatGPT Validator) опубликованы; фактическое выполнение пока NOT RUN.

Этот репозиторий — единственный публичный источник карточек и подготовленных промптов для Dispatcher. Обычная доставка не требует чтения приватного INBOX, приватных проектных репозиториев или локального GitHub-токена Dispatcher.

## Структура

- `contracts/<CONTRACT_ID>.md` — публичные карточки и зависимости.
- `prompts/<CONTRACT_ID>-<PROVIDER>.md` — полные промпты для исполнителей.
- `files/` — подготовленные резчиком исходники и SHA-манифесты (до 5 файлов на DeepSeek).
- `results/<DELIVERY_ID>.txt` — неизменённый полный оригинал ответа, сохранённый Publisher-промптом.
- `templates/` — шаблоны, не действующие задания.

## Маршрутизация моделей

- **DeepSeek:** текст и до пяти подготовленных файлов, встроенных в промпт; внешние GitHub/Drive-коннекторы не предполагаются.
- **ChatGPT:** может выполнять задания, требующие GitHub и/или Google Drive.
- **Gemini:** может выполнять задания с Google Drive и явным `drive_target`; GitHub-задания ему не назначаются.

Dispatcher выбирает модель по карточке, получает промпт и подготовленные файлы, затем передаёт текст в соответствующую вкладку Firefox. Доступ к аккаунту заранее не проверяется: если нужный коннектор недоступен, исполнитель сообщает об этом в ответе.

## Рабочий цикл

1. Dispatcher читает только этот публичный каталог.
2. Готовая карточка автоматически отправляется в подходящую живую вкладку.
3. Worker возвращает полный ответ; Dispatcher сохраняет оригинал и SHA локально.
4. Для DeepSeek Dispatcher формирует **Publisher-промпт** и отправляет его в ChatGPT. Publisher — роль/промпт, а не отдельная программа.
5. После Publisher SEND_CLICKED и 120 секунд Dispatcher открывает зависимые Validator-карточки. Validator получает динамические ID и SHA из локального журнала и проверяет публичный файл.
6. Отправка, захват ответа, публикация и независимая валидация — разные статусы.

## Ограничения

- Никакого приватного INBOX в обычном маршруте.
- Никакого локального GitHub-токена для чтения публичных карточек и промптов.
- Никакого предварительного подтверждения наличия GitHub/Drive-коннектора в каждой вкладке.
- Публичная карточка не означает PASS; Validator обязан читать фактический результат.
- Dispatcher не делает merge и deployment автоматически.
