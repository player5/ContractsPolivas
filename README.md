# ContractsPolivas — публичный каталог BROWN SWARM

**Активная задача:** C001D000TST (DeepSeek, тестовая карточка).
**V002D001TST:** сохранён как шаблон независимой проверки; **автоматически не запускается**.

Этот репозиторий — публичный источник карточек и полных промптов. Dispatcher читает его без GitHub-токена и без приватного INBOX.

## Структура

- `contracts/<CONTRACT_ID>.md` — карточки заданий.
- `prompts/<CONTRACT_ID>-<PROVIDER>.md` — полные промпты.
- `files/` — подготовленные резчиком файлы и SHA-манифесты (для DeepSeek — до пяти файлов).
- `results/<DELIVERY_ID>.txt` — полный оригинальный ответ, записанный Publisher-промптом.
- `templates/` — неактивные шаблоны.

## Исполнители

- **DeepSeek:** самодостаточный текст и до пяти встроенных подготовленных файлов; внешние коннекторы не предполагаются.
- **ChatGPT:** задания с GitHub и/или Google Drive.
- **Gemini:** задания с Google Drive; GitHub-задания ему не назначаются.

## Рабочий цикл

1. Dispatcher читает публичную карточку и полный промпт, получает подготовленные файлы.
2. Выбирает модель по карточке и отправляет промпт в соответствующую вкладку Firefox.
3. Worker забирает полный ответ и распознаёт конечный статус.
4. Если ответил DeepSeek, Dispatcher автоматически передаёт его полный оригинал в Publisher-промпт для ChatGPT (при недоступности — Gemini).
5. ChatGPT Publisher записывает оригинал в публичный `results/<DELIVERY_ID>.txt`; если используется Gemini fallback, он пишет в настроенную папку `BROWN_SWARM_HANDOFFS` на Google Drive. Publisher перечитывает файл и возвращает `BROWN_STATUS|<CONTRACT_ID>|DONE` только после подтверждённой записи.
6. Если ответ не захвачен за 10 минут, Dispatcher автоматически повторяет отправку; повторяется каждые 10 минут до захвата ответа.

Publisher — это промпт в обычном чате, не отдельная программа. Отдельный Validator не входит в обычный цикл.

## Стоп-слова

- `BROWN_STATUS|<CONTRACT_ID>|DONE` — задание завершено.
- `BROWN_STATUS|<CONTRACT_ID>|CONTINUE` — исполнитель продолжает.
- `BROWN_STATUS|<CONTRACT_ID>|BLOCKED` — исполнитель закончил с блокером.
- `BROWN_STATUS|<CONTRACT_ID>|ERROR` — исполнитель закончил с ошибкой.

`DONE` засчитывается только для правильного Contract ID. Для Publisher — только после записи и readback файла.


## Обязательный конечный статус Worker для новых промптов

Каждый новый рабочий промпт должен требовать, чтобы исполнитель закончил ответ **последней непустой строкой** в формате:

~~~text
BROWN_STATUS|<CONTRACT_ID>|<STATUS>|DELIVERY_ID=<DELIVERY_ID>; ITERATION=<N>; ATTEMPT=<N>; DETAIL=<SHORT_TEXT>
~~~

Статусы:

- `READY` — готово: назначенная порция завершена;
- `CONTINUE` — частично: требуется продолжение;
- `BLOCKED` — заблокировано внешним условием;
- `FAILED` — попытка завершилась неудачей;
- `NEED_INPUT` — требуется ответ постановщика/владельца.

Маркер должен содержать точные ID текущей доставки и попытки. После него нельзя добавлять текст. Отсутствующий, обрезанный или не совпадающий с карточкой маркер означает, что статус Worker не подтверждён; он не превращает ответ в PASS. `READY` означает только самоотчёт исполнителя о завершении своей порции.

**Совместимость:** текущий Firefox Worker v0.7.4 распознаёт `READY`, `CONTINUE`, `BLOCKED`, `SUBMITTED`; поддержка `FAILED` и `NEED_INPUT` должна быть добавлена и протестирована в транспортном парсере до массового использования этих значений в новых заданиях.

**Исключение старого теста:** C001D000TST использует конечную строку `я пидор` как специальный тестовый sentinel полного захвата хвоста. Сохранять её в этом тесте; не считать её статусом Worker и не переносить как обязательную фразу во все рабочие промпты.

Полная внутренняя спецификация роли Delivery Engineer и приёмки находится в канонической памяти BROWN COMMAND: `BROWN_COMMAND/DELIVERY_ENGINEER_SCOPE_AND_WORKER_STATUS_PROTOCOL_2026-11-22.md`.

## Ограничения маршрута

- Публичный каталог — единственный источник карточек в обычном маршруте.
- Приватный INBOX не читается.
- Dispatcher не хранит и не требует GitHub-токен для чтения публичных заданий.
- Publisher использует подключение своего чата для записи результата.
- V002 оставлен в репозитории как шаблон, но имеет статус TEMPLATE и не отправляется автоматически.
