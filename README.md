# ContractsPolivas — публичные задания BROWN SWARM

**Текущая очередь:** [INDEX.md](INDEX.md). **Готов 1 контракт C001D000TST**, зависимый **V002C001TST ожидает публикации C001**. Это два независимых задания: DeepSeek пишет ровно 100 слов о работе автоматизированного макаронного завода, ChatGPT Validator сверяет соответствие и выдаёт подробный отчёт.

| Контракт | Модель | Назначение | Статус |
|---|---|---|---|
| [C001D000TST](contracts/C001D000TST.md) | DeepSeek | Текст строго 100 слов | PUBLISHED / READY / I2 A1 |
| [V002C001TST](contracts/V002C001TST.md) | ChatGPT | Независимая проверка количества слов, содержания, структуры, статуса и SHA | WAITING_PUBLICATION / D001 |

**Нумерация:** [NUMBERING.md](NUMBERING.md). Первая буква — роль, три цифры — сквозной номер, следующая буква — назначенная модель **D=DeepSeek, G=Gemini, C=ChatGPT**, далее три цифры зависимости, затем серия (TST). Конечная F — срочный фикс, создаваемый Validator до интеграции: приоритет перед обычными готовыми контрактами, но не выше обязательных зависимостей.

## Как работает автоматическая цепочка

1. Dispatcher читает [INDEX.md](INDEX.md), карточку и полный промпт по публичному Raw HTTPS, без GitHub API/токена. Не выполняет специальных проверок по конкретным номерам и не назначает новые порядковые номера.
2. Маршрутизирует по модели карточки в правильную Firefox-вкладку, открывает новую беседу **в той же вкладке**, отправляет полный промпт.
3. Сохраняет полный оригинальный ответ, фиксирует SHA-256 и передаёт отдельный Publisher-промпт свободному ChatGPT.
4. Publisher в авторизованном ChatGPT сохраняет точный оригинал в `results/<DELIVERY_ID>.txt`, читает обратно байты, сравнивает SHA и **только затем** переводит исходную карточку в `PROCESSED`, убирает её из активного INDEX и активирует готовые зависимые задания. История, другие задания и результаты сохраняются.
5. Dispatcher независимо перечитывает публичный файл и убеждается, что байты совпадают с сохранённым оригиналом. Только это открывает GATE зависимостей. Истечение таймера не является PASS.
6. Validator получает оригинальный полный промпт, ссылку на исходный результат и реальный исходный SHA. После независимого отчёта результат Validator тоже публикуется, и его карточка выводится из активной очереди.
7. При выявлении дефекта Validator готовит срочный фикс с конечной F; он выполняется перед обычными готовыми заданиями, сохраняя GATE зависимостей.

**Ответственность:** Dispatcher не пишет в GitHub анонимно; редактировать `INDEX.md` и карточки может только Publisher/Producer с разрешённым доступом к репозиторию. Если нет GitHub-доступа или SHA не сходится, источник остаётся не подтверждённым и Validator не запускается. Изменения результата, не подтверждённые реальным readback, не принимаются.

**Структура:** `contracts/` — актуальные карточки, `prompts/` — полные задания, `files/` — подготовленные входные файлы, `results/` — оригинальные сохранённые результаты, `INDEX.md` — активная очередь, `NUMBERING.md` — схема ID.

**Состояние испытания:** исходники/локальные тесты универсального Dispatcher собраны, но реальная автоматическая цепочка в браузере **NOT VERIFIED**. Никаких самоназначенных PASS.

Старые тестовые карточки и промпты удалены из текущего дерева согласно поручению владельца; их Git-коммиты остаются в истории. Диагностический старый файл результата сохранён, поскольку это не контракт.
