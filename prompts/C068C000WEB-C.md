Создать отдельный постоянный тестовый модуль SEKA UI Lab v0, используя как основу существующий четырёхстраничный seka.ui027_demo; исходный пример не менять. Лаборатория должна устанавливаться одной папкой и использовать только публичный API v1 без специальных патчей ядра.

## Критерии готовности
1. Четыре функциональных раздела: DataTable с фильтром/сортировкой/страницами/выбором/редактированием; Tree с lazy/expand/context/reorder; Form/Dialog с реальной серверной валидацией/submit; webWidget с sandbox и подтверждаемым событием.
2. Нажатие вызывает backend; успех только после ACK новой revision. При ошибке показывается корректный отказ, а данные не меняются.
3. Тесты на два пользовательских контекста, 403, 409, невалидные события, XSS, перезагрузку. RAM-состояние явно помечено как DEMO RAM ONLY, не выдаётся за durable storage.
4. Отчёт по реальному запуску API, по возможности Chromium, с NOT RUN для отсутствующих проверок.

### Проверки, формат результата
Предоставь изолированный набор исходников, точный GitHub commit/branch или полный текстовый handoff если GitHub write недоступен, краткую инструкцию запуска, `integration_handoff`, тесты новых функций и регрессии существующего API v1. Публикуй исходники в закрытом SEKA_WEB, не в открытом каталоге контрактов. Worker не открывает GATE и не принимает собственный релиз.
