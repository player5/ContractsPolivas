# BROWN SWARM — утверждённая нумерация

Актуально для Dispatcher 0.9.10 / Worker 0.9.1 (V15). Локальные тесты PASS, живая приёмка NOT RUN. Порядок публикации: [CUTTER.md](CUTTER.md).

**Нижняя граница следующего нового сквозного номера: 108** (после публикации SEKA WEB C094–C105 и V106–V107, 25.11.2026; прежние номера не переиспользовать).

## Формат

ROLE + SERIAL + MODEL + BLOCKERS + SERIES [+ F].

- ROLE: C — основной исполнительский контракт, V — независимый Validator; другие роли только по проектному регламенту.
- SERIAL: общий для всех ролей, моделей и серий положительный порядковый номер. Минимум три цифры, переменная длина без отдельного числового потолка. Цифры читаются до следующей буквы. Сравниваются по числовому значению без переполнения. Ведущие нули не создают новые номера. Cutter использует минимальную десятичную запись, дополненную нулями до трёх цифр.
- MODEL: D — DeepSeek, G — Gemini, C — ChatGPT. Это не зависимость.
- BLOCKERS: 000 — единственное обозначение отсутствия блокеров; иначе один или несколько положительных номеров (минимум три цифры) через +. Номер может быть больше собственного; роль, модель и серия блокера не имеют значения. Нулевые, повторяющиеся и собственные номера в списке блокеров недопустимы.
- SERIES: три буквы, по проектному регламенту.
- F: срочный фикс Validator в конце ID; не новая роль. Такой фикс может использовать исходный номер и получает приоритет только среди готовых задач, не обходит зависимости. Причину, оригинал/коммит, границы и доказательства фиксировать отдельно; независимая валидация сохраняется.

Общий предел ID — 128 символов, delivery ID — 160 символов. При необходимости разделять зависимости через согласованные GATE. Старые трёхзначные ID остаются совместимы.

## Маршрутизация

Обычная совместимая роль C: код модели определяет предпочтительного исполнителя и исходный тип результата. Сначала собственные готовые задачи, затем свободные совместимые D→G→C или G→C. C не понижается. Специальные роли закреплены. Неизвестные требования к возможностям не разрешают перелив. Явный executor в карточке должен соответствовать ID; фактического исполнителя Dispatcher записывает отдельно. D-текст остаётся текстом при переливе, G-файл остаётся файлом. GPT: доставка, собственные задачи, затем перелив; отправленное задание не прерывать.

При корректном BLOCKED обычной совместимой роли C новая попытка A+1 у более старшего совместимого исполнителя. При занятости промежуточного допускается следующий совместимый. Не повторять у уже ответившей BLOCKED модели. BLOCKED GPT завершает автоматическую эскалацию; контракт остаётся активным. Специальные роли, NEED_INPUT и ERROR автоматически не эскалируются. Сохранять ID, итерацию, тип результата, права, блокеры и прежние ответы. Транспортные DISPATCH-/PUBLISH- и I/A не меняют номер контракта. Validator учитывает все попытки, не выдаёт неоднозначный результат за PASS.

## Зависимости и транспорт

Только успешное чтение корректного актуального INDEX определяет активные номера. Пока любой блокер присутствует, зависимый контракт ждёт. Ошибка карточки не снимает блокер. Ошибка чтения не означает пустой INDEX. Получение ответа не снимает блокер.

Dispatcher — курьер, не пишет в GitHub и не проверяет качество, SHA публикации или PROCESSED. Обычным контрактам добавляет уникальный BROWN_FINISH|v1|contract|delivery|command|STATUS. DONE/BLOCKED/NEED_INPUT/ERROR означают окончание ответа, не независимую приёмку. D/G-результаты доставляются GPT независимо от готовности Validator. Служебный пакет не требует ответа/маркера GPT. GPT сохраняет фактический текст/находит файл и удаляет соответствующую строку INDEX только после подтверждения результата; при неудаче оставляет. Исчезнувший ID Dispatcher не переотправляет, локальная история сохраняется. Не нужен отдельный Publisher. Содержательную проверку выполняет независимый Validator.
