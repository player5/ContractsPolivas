# BROWN SWARM — утверждённый формат номеров контрактов

**Статус: УТВЕРЖДЕНО владельцем, 2026-11-23.** Исправлено прежнее ошибочное толкование буквы D как «зависимость».
**Сфера:** Cutter/Producer, публичный каталог ContractsPolivas, очередь Dispatcher.

## Формат ID

`<ROLE><NNN><MODEL><DEP><SERIES>[F]`

| Часть | Значение |
|---|---|
| `ROLE` (первая буква) | `C` — основной исполнительский контракт; `V` — независимый Validator; другие роли только по проектному регламенту |
| `NNN` | **Сквозной** порядковый трёхзначный номер, общий для разных типов контрактов |
| `MODEL` | **`D` — DeepSeek, `G` — Gemini, `C` — ChatGPT**. Эта буква **не означает зависимость** |
| `DEP` | Три цифры. `000` — нет зависимости; `001` — зависимость от контракта с общим порядковым №001; полные `depends_on` перечислены в карточке |
| `SERIES` | Например `TST` — тестовая серия |
| `F` на самом конце | **Срочный фикс, созданный валидатором** по замечанию до интеграции. Выполняется **вне обычной очереди**, но **только после выполнения собственных зависимостей/GATE** |

**Точная пара текущего теста:**
- **`C001D000TST`** — основное задание №001 для DeepSeek, без зависимости.
- **`V002C001TST`** — Validator №002 для ChatGPT, зависимость от задания с номером 001 (`depends_on: C001D000TST`).

**Пример возврата:** Validator может создать срочное исправление `C001D000TSTF` (буква **F в конце**, не новый номер `F003`). Такое исправление имеет приоритет над обычными готовыми задачами, но не игнорирует невыполненные зависимости.

## Практические правила

1. Новые обычные номера резервирует Producer/Cutter с проверкой реестра и истории **в общей сквозной последовательности**. Dispatcher не придумывает NNN сам.
2. Буква модели — только реальная назначенная модель. Исполнитель указан и в карточке `executor`; несовпадение кода модели с `executor` — ошибочная карточка, не выдавать.
   **ЖЁСТКОЕ ЗАКРЕПЛЕНИЕ:** если карточка или ID указывает D/G/C, выдавать только указанному исполнителю. Если он занят — ждать свободного слота; не подменять другой моделью. D < G < C применяется только к неназначенным заданиям до публикации окончательного ID, при совпадении возможностей и прав. Заняты D → можно рассмотреть G, затем C только для таких свободных заданий. Противоречащий ID/executor — BLOCKED, без самостоятельного исправления.
3. `DEP` задаёт зависимость по порядковому номеру, а `depends_on` — полные ID без двусмысленности. `000` означает отсутствие зависимостей.
4. Транспортные `DISPATCH-...`/`PUBLISH-...` и `I1-A3` (итерация/попытка) **не меняют** обычный номер контракта. При изменении задания фиксируй ревизию, новую итерацию/попытку или согласованную отдельную доставку.
5. Возврат `...F` оформляет именно Validator в пределах своих полномочий; причину, оригинальный контракт/коммит, границы исправления, приоритет, зависимости и требуемые доказательства фиксировать отдельно. `F` не является новой первой буквой роли и не отменяет независимую валидацию после исправления.
6. После фактической публикации результата и совпадения SHA-256 уполномоченный Publisher/Producer выводит исходную карточку из активного `INDEX.md` со статусом `PROCESSED`, сохраняет историю и активирует удовлетворённые зависимости. Сам `DONE` от модели, Send и 120 секунд не равны проверенной публикации.

## Актуальная очередь и реализация

В публичном `INDEX.md` активна только `C001D000TST` (DeepSeek, текст ровно на 100 слов); `V002C001TST` (ChatGPT Validator, зависит от №001) находится в `WAITING_PUBLICATION` до совпадения SHA исходного и опубликованного ответа. **Других актуальных тестовых контрактов нет.** Старые карточки/промпты удалены из текущего дерева владельцем разрешённой очисткой; Git-история коммитов остаётся.

**Реализовано локально в кандидате UNIVERSAL:** проверки ID по роли/модели/зависимости, общий Publisher с инструкцией переводить подтверждённые контракты в PROCESSED, доказательный SHA GATE, приоритет F, настраиваемые интервалы. **На живом ПК ещё NOT VERIFIED.** Работающий FIX12P4 не поддерживает новый GATE; для проверки этого каталога требуется новая универсальная сборка и обновление временного Firefox Worker. Dispatcher не владеет GitHub-токеном: статус в публичном индексе изменяет авторизованный Publisher/Producer.
