# BROWN SWARM — регламент постановщика (Cutter)

Актуальный регламент для Dispatcher 0.9.10 / Worker 0.9.1 (V15). Локальные тесты PASS; живая приёмка V15 NOT RUN.

## Нарезали → подхватили → сделали

1. Прочитай [INDEX.md](INDEX.md) и [NUMBERING.md](NUMBERING.md), сверь историю сквозных номеров и нижнюю границу следующего номера. Выбери реальные задания и назначенную модель. ID = роль + номер переменной длины (минимум три цифры) + D/G/C + 000 либо номера блокеров через + + серия из трёх букв + необязательный F. Блокеры могут иметь номера выше собственного. F приоритетен только среди готовых.
2. Для каждого задания создай полный самостоятельный текст в prompts/ и карточку contracts/<ID>.md. Минимальная карточка содержит две строки: поле contract_id со своим точным ID и поле prompt со ссылкой на соответствующий файл ../prompts/<ID>-<PROVIDER>.md. Шаблоны в templates/ необязательны для транспорта, их требования безопасности сохраняются.
3. Добавь строку в существующую шестиколонную таблицу INDEX.md: жирный ID, роль, имя назначенной модели, ссылка на карточку, ссылка на промпт, PUBLISHED. Сохрани чужие строки. Не публикуй секреты, закрытый код, внутренние адреса или персональные данные.
4. Перечитай INDEX и файлы. Dispatcher сам извлекает модель, блокеры, приоритет, delivery ID (по умолчанию PUB-<ID>-I1-A1) и добавляет точный BROWN_FINISH обычному контракту. Не задавай значения транспортного маркера заранее.

## Не нужно для обычной карточки

schema, executor, mode, blocker, depends_on, drive_target, required_capabilities, self_contained, prompt_blob_sha, revision, iteration, attempt, delivery_id и данные Validator/F не обязательны для транспорта. При необходимости постановщик вправе указать полезные исполнителю данные; явный executor соответствует коду ID, явный source pin совпадает с исходником. При наличии специальных ограничений доступа, source manifest или режима неполного задания сохраняй требуемые исходники и полномочия. Не придумывай доступ к GitHub/Drive для неподходящей модели. Повторную работу оформляй отдельной попыткой, не переиспользуй старую доставку.

## Исполнение

Только корректно прочитанный актуальный INDEX определяет активные номера. Пока хотя бы один блокер есть, зависимый контракт ждёт. После исчезновения всех — выдаётся. Ошибка чтения не равна пустой очереди. Карточка с ошибкой не мешает независимым заданиям и остаётся блокером по номеру.

D/G/C выполняют обычные контракты до точного финального маркера. Dispatcher забирает полный ответ D/G и передаёт результат GPT. Служебная доставка не требует ответа/маркера: факт отправки и готовность вкладки отдельно, закрытие источника — только исчезновение строки INDEX. GPT сохраняет/находит результат и удаляет соответствующую строку; если не удалось — оставляет. Никаких SHA результата, PROCESSED, отдельной роли Publisher или оценки качества диспетчером. Validator — обычный независимый контракт, также с маркером. Исполнители не удаляют карточки/результаты/историю; отдельная уборка только по указанию владельца.

## Уточнение владельца 25.11.2026 — V15 (Dispatcher 0.9.10 / Worker 0.9.1)
УТВЕРЖДЕНО: сквозной порядковый номер и каждый номер блокера имеют минимум три цифры, переменную длину без отдельного числового потолка. Формат ROLE + SERIAL + MODEL + BLOCKERS + SERIES [+ F]. Цифры читаются до следующей буквы; блокеры разделяются +. 000 — единственное обозначение отсутствия блокеров, нулевой номер контракта запрещён. Номера сравниваются по числовому значению без переполнения, ведущие нули не создают новые сквозные номера. Cutter выдаёт минимальную запись номера с дополнением нулями до трёх цифр; не переиспользовать номер из истории. Полный ID ограничен существующим транспортным пределом 128 символов, delivery ID — 160 символов; не публиковать слишком длинные ID, при необходимости разделять зависимости через согласованные GATE. Существующие трёхзначные ID, D/G/C, F, BROWN_FINISH, BLOCKED-эскалация и правила INDEX сохраняются. V15: локальные тесты PASS; живая приёмка NOT RUN; Worker 0.9.1 побайтно неизменен. Уточнение заменяет все прежние требования ровно трёх цифр.

## Уточнение владельца 25.11.2026 — V13 (Dispatcher 0.9.8 / Worker 0.9.0)
Утверждено: при фактическом BLOCKED с корректным финальным маркером обычного совместимого контракта C диспетчер назначает новую транспортную попытку A+1 более старшему совместимому исполнителю по D→G→C / G→C. При занятости промежуточного допускается следующий совместимый. Не повторять у уже ответившей BLOCKED модели. BLOCKED от GPT завершает автоматическую эскалацию; контракт остаётся активным. ID, итерация, исходный тип результата, ограничения доступа и блокеры сохраняются; прежний ответ не удаляется. Специальные роли закреплены, NEED_INPUT/ERROR не эскалируются автоматически. Validator ищет фактические результаты по ID с учётом всех попыток, а не только A1, не выдаёт неоднозначный или отсутствующий результат за PASS. Приоритет GPT: доставка, затем собственные готовые задачи, затем совместимый перелив; уже отправленную задачу не прерывать. V13 локальные испытания PASS; живая приёмка NOT RUN. Активный INDEX остаётся единственным источником снятия зависимостей.

## Обязательная инструкция Gemini для файлов Google Drive — утверждено владельцем 24.11.2026

Cutter обязан вставлять следующий порядок непосредственно в каждый новый промпт Gemini, требующий создания обычного файла на Drive (TXT, CSV, JSON, ZIP и другие форматы). Требование сохраняется при совместимом переливе задания на GPT. Для нативных документов Google Workspace применяются подходящие инструменты их создания.

1. Сначала полностью сформируй содержимое и создай реальный файл требуемого формата через доступный инструмент генерации файлов или исполнения кода (например Python).
2. Проверь файл по критериям задания, затем загрузи или экспортируй готовый файл на Google Drive доступным способом. Не пытайся создавать обычный TXT/CSV/JSON/ZIP как нативный документ Google Workspace.
3. Если один способ не работает, проверь доступные альтернативы: отдельно создание файла и отдельно его загрузку/экспорт. Ошибка создания нативного документа не доказывает невозможность загрузки обычного файла.
4. Проверь фактическое наличие файла на Drive и верни реальную ссылку. Не перезаписывай чужие файлы и не меняй права доступа без разрешения. Локальный файл, предпросмотр или кнопка экспорта сами по себе не доказывают сохранение на Drive.
5. DONE — только при фактическом выполнении требований; BLOCKED — если доступные разрешённые способы проверены и препятствие сохраняется. Укажи конкретный этап, испробованные способы и причину отказа. Не выдумывай возможности, ссылки или успешную загрузку. Транспортный маркер по-прежнему добавляет Dispatcher.


## Уточнение владельца 24.11.2026 — V12 (Dispatcher 0.9.7 / Worker 0.8.9)
Для обычных совместимых контрактов роли C код модели в ID задаёт предпочтительного исполнителя и тип результата, а не запрет перелива. Сначала выдаются собственные готовые задачи модели, затем свободные совместимые слоты принимают D→G→C, G→C; C не понижается. Специальные роли, включая Validator, остаются закреплёнными. Неизвестные требования к возможностям не разрешают перелив; явно указанные возможности проверяются. Постановщик сохраняет ID и исходный тип задачи; фактический исполнитель записывается Dispatcher отдельно. Например D-текст от Gemini/GPT остаётся текстовым результатом, а не файлом Drive. Явное поле executor при публикации должно соответствовать коду ID. Блокеры, F, BROWN_FINISH и закрытие по INDEX неизменны. Это уточнение заменяет прежний запрет подмены модели для указанных обычных контрактов. V12: локальные тесты PASS, живая приёмка NOT RUN.
