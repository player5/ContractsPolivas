# BROWN SWARM — короткий регламент постановщика (Cutter)

Утверждённое упрощение от 24.11.2026. Реализация Dispatcher 0.9.2 / Firefox Worker 0.8.6: локальные тесты PASS, живой тест новой версии ещё NOT RUN. Этот файл — краткий вход для новых чатов; при противоречии старым описаниям действует последнее решение владельца.

## Нарезали → подхватили → сделали

1. Прочитай актуальные INDEX.md и NUMBERING.md, сверь историю сквозных номеров. Выбери реальные задания и назначенную модель. ID = роль + собственный трёхзначный номер + D/G/C + 000 либо номера блокеров через + + серия из трёх букв + необязательный F. Блокеры могут иметь номера выше собственного. F приоритетен только среди готовых.
2. Для каждого задания создай полный самостоятельный текст промпта в prompts/ и карточку contracts/<ID>.md. Минимальная карточка — две строки (пример, не резервирование номера):

```md
- `contract_id`: `C547D000TST`
- `prompt`: [Задание](../prompts/C547D000TST-DeepSeek.md)
```

3. После создания файлов добавь строку в существующую активную шестиколонную таблицу INDEX.md, сохрани чужие строки:

```md
| **C547D000TST** | C | DeepSeek | [C547D000TST](contracts/C547D000TST.md) | [Задание](prompts/C547D000TST-DeepSeek.md) | PUBLISHED |
```

4. Перечитай INDEX и файлы. Всё. Диспетчер сам извлечёт назначенную модель, блокеры, приоритет, delivery ID (при отсутствии — PUB-<ID>-I1-A1) и добавит точный BROWN_FINISH обычному контракту. Не задавай значения транспортного маркера заранее.

## Не нужно для обычной карточки

schema, executor, mode, blocker, depends_on, drive_target, required_capabilities, self_contained, prompt_blob_sha, revision, iteration, attempt, delivery_id и данные Validator/F не обязательны для транспорта. При необходимости постановщик вправе указать полезные исполнителю данные, явный executor не должен противоречить ID, явный source pin должен совпадать. При наличии явных специальных ограничений доступа, source manifest или режима неполного задания сохраняй требуемые исходники и полномочия. Не придумывай доступ к GitHub/Drive для неподходящей модели. Повторную работу оформляй отдельной попыткой, не переиспользуй старую доставку.

## Исполнение

Только корректно прочитанный актуальный INDEX определяет активные номера. Пока хотя бы один блокер есть, зависимый контракт ждёт. После исчезновения всех — выдаётся. Ошибка чтения не равна пустой очереди. Карточка с ошибкой не мешает независимым заданиям и остаётся блокером по номеру.

D/G/C выполняют обычные контракты до точного финального маркера. Диспетчер забирает полный ответ D/G и передаёт результат GPT. Служебная доставка не требует ответа/маркера: факт отправки и готовность вкладки отдельно, закрытие источника — только исчезновение строки INDEX. GPT сохраняет/находит результат и удаляет соответствующую строку; если не удалось — оставляет. Никаких SHA результата, PROCESSED, отдельной роли Publisher или оценки качества диспетчером. Validator — обычный независимый контракт, также с маркером. Не удалять карточки/результаты/историю.
